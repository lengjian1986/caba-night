# CABAKURA 后台需求文档

## 1. 背景与目标

CABAKURA 是面向日本夜店/キャバクラ场景的预约平台 App。当前前台设计稿已覆盖首页、店铺、Cast、预约订单、取消退款、评价、优惠券、收据、我的页面、身份认证、通知和客服支持等流程。

后台以 LikeAdmin 为基础搭建，第一阶段目标是在 Docker 环境中完成管理后台能力，不污染本机环境。后台需要支撑前台 App 的业务数据维护、订单处理、审核、客服、退款和运营配置。

## 3. 用户与后台角色

后台至少需要以下角色：

| 角色 | 权限范围 |
|---|---|
| 平台超级管理员 | 全部后台菜单、系统配置、角色权限、数据导出、日志查看 |
| 平台运营 | 店铺、Cast、订单、优惠券、评价、通知、客服内容维护 |
| 客服人员 | FAQ、咨询工单、订单关联查询、用户沟通记录 |
| 审核人员 | 身份认证审核、评价审核、店铺/Cast资料审核 |
| 财务人员 | 支付记录、退款记录、收据记录、金额核对 |
| 店铺管理员 | 仅管理所属店铺、套餐、Cast、排班、订单确认和店铺相关咨询 |

权限需要按 LikeAdmin 的菜单、按钮、数据范围控制。店铺管理员必须做数据隔离，只能访问自己所属店铺的数据。

## 4. 核心后台模块

### 4.1 工作台

后台首页展示运营概况：

- 今日预约数、确认中订单、待退款订单、待处理客服、待审核身份认证。
- GMV、退款金额、优惠券使用量、评价待审核数。
- 订单状态分布、热门店铺、热门 Cast、用户增长。
- 快捷入口：新增店铺、处理订单、审核证件、处理客服、创建优惠券。

### 4.2 会员管理

对应前台 `MyPage`、身份认证、通知、收藏、支付方式。

功能需求：

- 会员列表：昵称、姓名、手机号、会员等级、会員ID、注册时间、状态、认证状态。
- 会员详情：基础资料、预约历史、收藏店铺、收藏 Cast、评价记录、优惠券、通知设置。
- 会员等级：如 Gold Member，支持等级名称、权益说明、积分/消费门槛。
- 钱包/余额：展示余额和变动记录，例如前台显示 `ウォレット残高 ¥12,800`。
- 支付方式：只展示脱敏卡号，例如 `VISA ****1234`，不保存完整卡号和 CVC。
- 用户状态：正常、禁用、注销申请中、已注销。
- 操作日志：后台修改会员资料、冻结账户、调整等级必须记录。

### 4.3 身份认证审核

对应 `電話番号認証`、`本人確認書類`、`本人確認ステータス`。

功能需求：

- 电话认证记录：手机号、验证码发送状态、认证时间、失败次数。
- 证件上传记录：证件类型、正面照片、背面照片、提交时间。
- 审核列表：待审核、审核中、通过、驳回。
- 审核操作：通过、驳回、要求重传，驳回时必须填写原因。
- 敏感信息保护：证件图片访问需要权限，后台操作要留审计日志。

状态建议：

| 状态 | 含义 |
|---|---|
| `not_started` | 未开始 |
| `phone_verified` | 电话已认证 |
| `document_pending` | 证件待提交或部分提交 |
| `reviewing` | 审核中 |
| `approved` | 审核通过 |
| `rejected` | 审核驳回 |

### 4.4 店铺管理

对应店铺列表、搜索、详情、套餐详情。

功能需求：

- 店铺列表：店名、区域、类型、评分、评论数、营业状态、预约状态、最低价格。
- 店铺资料：日文名/假名、地址、最近车站、步行时间、营业时间、标签、简介。
- 图片管理：首页图、详情图、环境图、Logo。
- 营业执照：店铺入驻或资料提交时必须上传营业执照/营业许可相关文件，后台支持查看、下载、重新上传和版本留存。
- 店铺审核：新增店铺、营业执照变更、关键资料变更后进入审核流程，审核通过后才允许前台展示和开放预约。
- 审核操作：通过、驳回、要求补充资料；驳回或补充资料时必须填写原因，并通知店铺管理员或平台运营。
- 营业设置：营业中、休息中、今日可预约、临时停业。
- 价格区间：最低价、最高价、单位时长，例如 `¥10,000~¥18,000 / 60分`。
- 标签配置：高級感、明朗会計、当日予約OK、落ち着いた上質空間等。
- 店铺排序：推荐排序、首页热门、搜索权重。

店铺审核状态建议：

| 状态 | 含义 |
|---|---|
| `draft` | 草稿，资料未提交 |
| `submitted` | 已提交，待审核 |
| `reviewing` | 审核中 |
| `approved` | 审核通过，可展示/可预约 |
| `rejected` | 审核驳回 |
| `supplement_required` | 需要补充资料 |
| `suspended` | 平台暂停展示或暂停预约 |

### 4.5 套餐/Set Plan 管理

对应 `Shop Set Plan Detail` 和预约流程。

功能需求：

- 套餐列表：所属店铺、套餐名、时长、价格、原价、折扣、是否含税/服务费。
- 套餐详情：适用人数、预约截止时间、饮放题、初回限定等标签。
- 库存/可预约控制：按日期、时间段、人数限制可预约。
- 状态：上架、下架、售罄、仅指定用户/等级可见。

### 4.6 Cast 管理

对应 Cast 列表、搜索、详情、照片、出勤、评论。

功能需求：

- Cast 列表：姓名、所属店铺、年龄、身高、三围、评分、收藏数、出勤状态。
- Cast 资料：个人简介、标签、照片、排序、是否新人、是否排名展示。
- 出勤排班：日期、开始时间、结束时间、是否可预约、最短可预约时间。
- Cast 照片：主图、详情图、相册图，支持排序。
- 标签：会話上手、気配りが上手、写真通り、また会いたい等。
- 数据隔离：店铺管理员只能管理本店 Cast。

### 4.7 搜索与推荐配置

对应前台 `AIでお店を探す`、店铺/Cast搜索、筛选、排序。

功能需求：

- 搜索关键词管理：热门关键词、推荐词、禁用词。
- 筛选项配置：区域、营业状态、本日予約可、割引あり、出勤中、新人、ランキング。
- 推荐规则：首页热门店铺、Cast推荐、搜索默认排序。
- 权重配置：评分、评论数、预约转化、运营置顶。

### 4.8 预约订单管理

对应预约列表、预约详情、预约步骤、确认中、预约完成。

功能需求：

- 订单列表：订单号、用户、店铺、套餐、Cast、来店时间、人数、金额、支付状态、预约状态。
- 订单详情：预约信息、支付信息、优惠券、二维码核销信息、状态时间线。
- 店铺确认：前台有 `店舗確認中`、`予約確定`，后台需要支持店铺确认/拒绝预约。
- 变更管理：人数、时间、Cast、套餐变更记录。
- 二维码核销：用户来店时展示 QR，后台或店铺端可核销。
- 订单备注：平台备注、店铺备注、客服备注分离。

预约状态建议：

| 状态 | 含义 |
|---|---|
| `requesting` | 预约请求中，等待店铺确认 |
| `confirmed` | 预约已确认 |
| `unpaid` | 未决済 |
| `paid` | 已支付 |
| `visited` | 已来店/已核销 |
| `completed` | 已完成 |
| `cancel_requested` | 用户提交取消 |
| `cancelled` | 已取消 |
| `refund_pending` | 退款处理中 |
| `refunded` | 已退款 |
| `refund_failed` | 退款失败 |

### 4.9 订单取消与退款

对应 `Order Cancel Case 01-03`。

前台流程：

1. 输入取消理由，系统展示返金見込み。
2. 用户确认取消内容。
3. 取消受付完了，显示返金処理待ち。

功能需求：

- 取消理由配置：予定が合わなくなった、時間を変更したい、店舗と連絡が取れない等。
- 取消申请：订单号、用户、理由、详细说明、申请时间。
- 费用计算：支付金额、取消料、返金予定額、返金先。
- 退款记录：退款渠道、退款金额、退款状态、第三方流水号。
- 取消规则：按来店前时间、店铺、套餐、会员等级配置取消费。
- 财务审核：高金额或异常退款可进入人工审核。

退款状态建议：

| 状态 | 含义 |
|---|---|
| `not_required` | 无需退款 |
| `pending` | 退款处理中 |
| `processing` | 第三方退款中 |
| `success` | 退款成功 |
| `failed` | 退款失败 |
| `manual_review` | 人工确认中 |

### 4.10 支付管理

对应前台支付确认、卡片管理、退款展示。

功能需求：

- 支付记录：订单号、支付金额、支付方式、支付状态、支付时间、交易流水号。
- 卡片信息：只存支付渠道 token 和脱敏信息。
- 支付回调：记录回调原文、处理结果、失败重试。
- 退款回调：记录退款状态同步。
- 对账导出：按日期、店铺、支付状态导出。

### 4.11 优惠券管理

对应 `MyPage Coupon`、`Coupon Detail`、`Order Coupon Apply`。

功能需求：

- 优惠券列表：名称、类型、面额/折扣、有效期、状态、可用数量。
- 适用范围：店铺、区域、Cast、套餐、会员等级、最低消费。
- 使用规则：是否可叠加、每人限用次数、总使用次数。
- 发放方式：后台手动发放、活动发放、注册赠送、会员等级专属。
- 使用记录：订单、用户、抵扣金额、使用时间。

### 4.12 评价管理

对应店铺评价、Cast评价、评价提交成功。

功能需求：

- 店铺评价：订单、用户、店铺、评分、标签、内容、图片。
- Cast评价：订单、用户、Cast、评分、标签、内容。
- 审核状态：待审核、已发布、已驳回、用户编辑中。
- 标签管理：雰囲気が良い、接客が丁寧、会話が楽しい、気配りが上手等。
- 展示控制：置顶、隐藏、删除、举报处理。

### 4.13 收据管理

对应 `領収書発行` 输入、确认、完成。

功能需求：

- 收据申请：订单号、店铺名、利用日時、合计金额、宛名、但し書き。
- 收据确认：用户确认后生成 PDF。
- PDF 管理：生成状态、下载地址、重新生成、作废。
- 财务导出：按日期、店铺导出收据记录。

状态建议：`draft`、`confirming`、`issued`、`voided`、`failed`。

### 4.14 客服与 FAQ

对应 `ヘルプ・サポート`、FAQ详情、客服对话。

功能需求：

- FAQ 分类：予約について、予約変更、キャンセル、来店前、支払い・領収書、本人確認、店舗・キャスト。
- FAQ 内容：问题、答案、分类、标签、排序、浏览量、是否热门。
- 客服工单：用户、订单号、咨询分类、内容、状态、处理人。
- 聊天消息：用户消息、客服回复、系统消息、发送时间、已读状态。
- 订单关联咨询：选择订单号后发起咨询，客服可直接查看订单摘要。
- 服务时间配置：例如 `10:00 - 24:00`。

工单状态建议：

| 状态 | 含义 |
|---|---|
| `open` | 新建 |
| `pending_operator` | 等待客服回复 |
| `pending_user` | 等待用户补充 |
| `resolved` | 已解决 |
| `closed` | 已关闭 |

### 4.15 通知管理

对应通知设置、通知列表。

功能需求：

- 通知模板：预约确认、来店前提醒、取消/退款、收藏店铺空席、Cast出勤、优惠券。
- 发送渠道：App Push、站内通知、SMS、邮件。
- 用户订阅设置：按通知类型开关。
- 通知记录：标题、内容、目标用户、发送状态、阅读状态。
- 群发能力：按会员等级、区域、收藏、最近预约筛选发送。

### 4.16 内容与运营配置

功能需求：

- 首页配置：热门店铺、推荐 Cast、Banner、活动入口。
- 区域管理：东京、新宿、歌舞伎町等。
- 标签字典：店铺标签、Cast标签、评价标签、FAQ标签。
- 协议与帮助内容：隐私政策、使用条款、取消政策、退款说明。
- 文件管理：图片、证件、PDF、客服附件。

### 4.17 系统管理

基于 LikeAdmin 保留并扩展：

- 管理员账号、角色、菜单权限、按钮权限。
- 操作日志、登录日志、异常日志。
- 数据字典、系统配置、定时任务。
- 文件存储配置、短信配置、邮件配置、支付配置。

## 6. 前台 API 分组

后台实现时需要同步提供或预留以下 App API：

- 首页：推荐店铺、推荐 Cast、热门区域、Banner。
- 店铺：列表、筛选、详情、套餐、收藏。
- Cast：列表、筛选、详情、照片、出勤、收藏。
- 预约：创建预约、确认预约、支付、详情、列表、二维码核销状态。
- 取消退款：取消试算、提交取消、确认取消、取消完成、退款状态。
- 支付：支付方式列表、添加/删除卡、发起支付、支付回调结果查询。
- 优惠券：我的优惠券、优惠券详情、预约时可用优惠券。
- 评价：提交店铺评价、提交 Cast 评价、评价结果。
- 收据：申请、确认、生成、下载。
- 我的页面：用户资料、收藏、会员等级、钱包、通知设置。
- 身份认证：短信发送、短信验证、证件上传、提交审核、审核状态。
- 客服：FAQ分类、FAQ列表、FAQ详情、创建工单、发送消息、消息列表。
- 通知：通知列表、已读、通知设置。

## 7. 后台页面交互要求

所有业务列表建议统一具备：

- 搜索：关键词、状态、时间范围、店铺、用户。
- 表格：分页、排序、状态标签、关键金额/时间展示。
- 操作：查看、编辑、启用/禁用、审核、导出。
- 批量操作：批量上架、批量下架、批量审核、批量导出。
- 详情页：基础信息、关联订单/用户/店铺、状态时间线、操作日志。
- 导出：订单、支付、退款、收据、评价、会员。

## 8. 非功能要求

- 环境：所有后端依赖在 Docker 中运行，避免污染本机环境。
- 权限：菜单权限、按钮权限、数据范围权限都要可控。
- 审计：身份认证、退款、订单状态、支付配置、权限变更必须留审计日志。
- 隐私：手机号、证件、卡号、支付信息默认脱敏展示。
- 安全：证件图片和收据 PDF 需要鉴权访问，不能直接公开裸链。
- 幂等：支付回调、退款回调、订单状态变更需要幂等处理。
- 可追溯：订单、退款、客服、审核均需要状态时间线。
- 国际化：前台主要文案为日文，后台字段可中文管理，但前台展示内容需要支持日文。

## 12. 需求补充

### 12.1 店铺账号与数据范围

店铺管理员不是独立子项目入口，而是同一个后台里的受限角色。后台需要支持把管理员账号绑定到一个或多个店铺，并按绑定关系限制数据访问。

补充需求：

- 店铺账号绑定：管理员可绑定单店铺或多店铺。
- 数据范围：店铺管理员只能查看和操作所属店铺的店铺资料、套餐、Cast、排班、预约订单和店铺相关客服工单。
- 操作限制：店铺管理员不能审核自己的店铺资料、营业执照或 Cast 资料；审核动作必须由平台侧角色完成。
- 登录后菜单：同一套业务菜单按角色显示，不出现单独的项目入口。
- 审计日志：店铺管理员所有确认订单、拒绝订单、修改排班、修改套餐、回复客服都要记录。

建议新增或明确数据对象：

| 对象 | 说明 |
|---|---|
| `shop_admin_relation` | 后台管理员与店铺绑定关系 |
| `data_scope_rule` | 角色/管理员数据范围规则，可先用代码规则实现 |

### 12.2 预约库存、时间段与防超卖

预约不是普通订单创建，必须校验店铺营业时间、套餐可预约规则、Cast 出勤、人数容量和支付状态。

补充需求：

- 时间段配置：店铺营业时间、套餐可预约时间、Cast 出勤时间需要统一判断。
- 容量控制：按店铺、套餐、Cast、日期、时间段限制预约数量和人数。
- 防重复预约：同一用户同一时间段、同一订单支付中状态需要做重复提交拦截。
- 状态锁定：用户发起预约后，后台确认前需要保留短时间名额；超时未支付或未确认时释放。
- 异常处理：店铺临时停业、Cast 临时请假、套餐下架时，已有订单需要进入变更/取消处理。

建议新增或明确数据对象：

| 对象 | 说明 |
|---|---|
| `reservation_slot` | 可预约时间段与容量 |
| `reservation_lock` | 预约临时锁定记录 |
| `shop_closure` | 店铺临时停业/特殊营业日 |
| `cast_absence` | Cast 临时请假/不可预约记录 |

### 12.3 订单金额快照与费用明细

订单创建后不能只关联当前套餐价格，否则套餐价格变更会影响历史订单和退款金额。

补充需求：

- 订单快照：保存下单时的店铺名、套餐名、Cast名、价格、税费、服务费、优惠券抵扣。
- 金额字段：支付金额、商品金额、服务费、税额、优惠金额、取消费、返金予定額分开存储。
- 退款依据：退款试算必须基于订单快照和取消规则快照，不直接读取当前配置。
- 展示一致：后台订单详情、取消确认页、收据 PDF 使用同一份金额快照。

建议新增或明确数据对象：

| 对象 | 说明 |
|---|---|
| `order_amount_snapshot` | 订单金额快照 |
| `order_cancel_policy_snapshot` | 下单时适用的取消规则快照 |

### 12.4 日本合规与年龄限制

项目面向日本夜店/キャバクラ场景，需要把年龄、实名、内容展示和营业许可要求写入后台规则。

补充需求：

- 年龄限制：用户身份认证需要判断是否达到服务允许年龄，未通过认证或年龄不满足时限制预约。
- 营业许可：店铺必须上传营业执照/营业许可文件，审核通过后才允许展示和开放预约。
- Cast 内容：Cast 资料、照片、评价内容需要支持平台审核和下架。
- 隐私保护：证件、营业执照、支付 token、手机号等敏感数据必须鉴权访问，后台默认脱敏。
- 数据保留：订单、支付、退款、收据、审核日志需要配置保留周期，删除用户时不能破坏财务和审计记录。

### 12.5 客服工单升级与附件

当前文档已有客服工单和消息，但还需要补充工单升级、内部备注、附件和 SLA。

补充需求：

- 工单分类：预约咨询、取消退款、支付收据、身份认证、店铺/Cast、账号问题。
- 工单优先级：普通、紧急、高金额退款、投诉。
- 工单升级：客服可升级给平台运营、财务或审核人员。
- 内部备注：客服内部备注不展示给用户。
- 附件：用户和客服可上传图片或文件，附件必须鉴权访问。
- SLA：记录首次响应时间、最后回复时间、解决时间，工作台显示超时工单。

建议新增或明确数据对象：

| 对象 | 说明 |
|---|---|
| `support_ticket_assignment` | 工单分配/转派记录 |
| `support_attachment` | 工单附件 |
| `support_internal_note` | 客服内部备注 |

### 12.6 通知触发点

通知不只是后台群发，还需要由核心业务状态变化自动触发。

补充通知事件：

- 预约提交成功。
- 店铺确认预约。
- 店铺拒绝预约。
- 来店前提醒。
- 取消申请提交。
- 退款处理中。
- 退款成功或失败。
- 身份认证通过、驳回、要求重传。
- 店铺审核通过、驳回、要求补充资料。
- 客服有新回复。
- 优惠券发放或即将过期。

每条通知记录需要保存触发业务对象、模板版本、发送渠道、发送状态、失败原因和阅读状态。

### 12.7 后台验收标准

第一阶段后台完成时，至少需要满足以下验收标准：

- 管理员可以创建店铺并上传营业执照。
- 店铺审核通过后，店铺才能进入可展示/可预约状态。
- 管理员可以维护套餐、Cast、Cast 排班。
- 会员列表、身份认证审核、订单列表、客服工单可按状态筛选。
- 订单可以完成确认/拒绝/取消申请/退款人工处理状态流转。
- 取消退款页面展示的支付金额、取消费、返金予定額、返金先与后台一致。
- 客服可以基于订单创建工单并回复消息。
- 权限管理、系统设置保留，LikeAdmin 默认业务/演示菜单不作为项目功能入口展示。
- 所有审核、退款、订单状态变更都有操作日志。
- 直接刷新后台业务 URL 不出现 404。
